12 ключевых сценариев платформы KARVON по актуальному ТЗ v3.2
1. Регистрация и вход (OTP)
sequenceDiagram autonumber actor U as Польз-ль participant API as API participant GW as GW participant DB as DB U->>API: POST /auth/send-otp API->>DB: OTP (TTL 5м) API->>GW: отправить код GW-->>U: код U->>API: POST /auth/verify-otp API->>DB: проверить OTP alt новый API->>DB: User (tokens=5) API-->>U: 201 is_new=true U->>API: POST /auth/complete-reg API-->>U: 200 OK else известный API-->>U: 200 is_new=false end API-->>U: access+refresh
2. Верификация компании
sequenceDiagram autonumber actor U as Польз-ль participant API as API participant DB as DB participant SMTP as SMTP actor M as Модератор U->>API: POST /companies API->>DB: status=pending M->>API: GET /moderator/queue alt approve M->>API: POST /queue/:id/approve API->>DB: status=approved API->>DB: notification: approved API->>SMTP: Email API-->>U: In-app notif else reject M->>API: POST /queue/:id/reject API->>DB: status=rejected API->>DB: notification: rejected API->>SMTP: Email U->>API: Исправить и подать снова else request-docs M->>API: POST /queue/:id/request-docs API->>DB: status=docs_requested API->>DB: notification: docs API->>SMTP: Email U->>API: Обновить → pending API->>DB: status=pending end
approved
In-app уведомление
Email на company.email
1 бесплатное активное объявление на аккаунт
rejected
rejection_reason в БД
In-app + Email уведомление
Можно подать снова после исправления
docs_requested
docs_request_note в БД
In-app + Email уведомление
После обновления → pending
📧 SMTP опционален: если SMTP_HOST не задан в .env — email-отправка отключена (no-op), in-app уведомления работают всегда.
3. Создание объявления — квота и оплата
sequenceDiagram autonumber actor U as Польз-ль participant API as API participant DB as DB participant R as Rahmat U->>API: POST /listings/cargo alt не авторизован API-->>U: 401 else нет компании API-->>U: 403 end API->>DB: COUNT free_active cargo+warehouse alt COUNT = 0 API->>DB: status=active, is_paid=false API-->>U: 201 active (бесплатно) else COUNT > 0 API->>DB: status=archived, is_paid=false API-->>U: 201 archived (квота занята) Note over U,R: оплата активирует U->>API: POST /payments/create API->>R: create invoice R-->>U: checkout_url U->>R: Оплатить R->>API: webhook success API->>DB: is_paid=true, status=active API-->>U: объявление активно end
Первое объявление (бесплатно)
1 объявление на аккаунт — бесплатно.
Считаются оба типа: cargo + warehouse вместе.
status=active сразу.
Второе и последующие
Создаются с status=archived (скрыто).
Оплата через /payments/create (type=listing)
→ is_paid=true, status=active.

6. Boost объявления

7. Статусы объявления — груз и склад
sequenceDiagram autonumber actor U as Польз-ль participant API as API participant DB as DB alt первое (квота свободна) U->>API: POST /listings/cargo API->>DB: status=active, is_paid=false else квота занята U->>API: POST /listings/cargo API->>DB: status=archived, is_paid=false Note over U,DB: оплата → active API->>DB: is_paid=true, status=active end U->>API: PATCH /:id/status API->>DB: in_stock=false U->>API: PATCH /:id/status archived API->>DB: status=archived U->>API: PATCH /:id/status active API->>DB: status=active U->>API: DELETE /:id API->>DB: delete
active
Видно в поиске
is_boosted=true → вверху листинга
in_stock=false

После оплаты → active
